# 内置工具记录、展示与回传需求

## 1. 文档信息

- 状态：已实现，待评审
- 平台：iOS、Android
- 需求边界：服务端执行的内置工具（web_search、code_interpreter、shell）的调用记录展示、结果展示、跨模型回传
- 关联需求：
  - [对应技术设计](builtin-tools-tech.md)
  - [自定义请求控制需求](request-controls-prd.md)（内置工具由用户通过请求控制开启）

## 2. 背景

部分服务商在服务端执行内置工具，工具调用与结果内联在同一条助手消息里返回，与思维链交错出现。当前 App 只持久化文本、媒体引用、函数调用（客户端工具）及其结果，内置工具项被整体丢弃，导致：

- 用户看不到模型这一轮调用了哪个内置工具、参数是什么、结果是什么。
- 下一轮请求无法把内置工具项按原序回传，模型无法感知上一轮的工具结果。

本需求让内置工具项作为一等中立内容被记录、展示，并在同服务商家族内可跨模型回传。

## 3. 目标

1. 采集助手消息中所有内置工具项，按服务端返回的原始顺序保留。
2. 全量持久化每个内置工具项的原始结构，App 重启后仍可展示和回传。
3. 展示调用记录：让用户知道这一轮调用了哪个内置工具及其参数。
4. 展示工具结果，按结果所在位置分类呈现。
5. 同一服务商家族内跨模型回传内置工具项，使模型保持对上一轮结果的记忆。
6. 通用设计：初版支持 web_search、code_interpreter、shell，新增内置工具无需改动数据模型即可承载。

## 4. 非目标

- 不负责开启内置工具。是否发送 `tools`、是否设置 `include` 额外返回字段，完全由用户通过自定义请求控制配置。
- 不解析、不重排、不裁剪内置工具项的内部结构；原样保存、原样回传。
- 不跨服务商家族回传内置工具项。切换到不支持该结构的家族（Chat Completions、Anthropic 等）时整体丢弃。
- 不改变现有 reasoning 回传的跨模型隔离规则。
- 不改变函数调用（客户端工具）的现有展示与回传。
- 不升级数据库版本、不新增数据库列。

## 5. 采集与持久化

1. 从流式响应的终态事件采集内置工具项。终态事件携带完整、等价的输出数组；流式过程中的中间事件不作为采集依据。
2. 每个内置工具项作为一个独立的有序内容片段保存，记录：类型、服务端项 ID、状态，以及该项的完整原始结构。
3. 内置工具项与文本、函数调用等其他片段共享同一条助手消息的顺序，保留服务端返回的相对位置。
4. 原始结构全量落库，不做字段筛选，以支持未来新增字段与精确回传。
5. 采集为兜底式：除已有专线处理的类型（文本、reasoning、函数调用）外，其余任何输出项一律原样采集，不维护支持类型清单。
6. `include` 决定服务端是否返回某些结果字段。用户未开启对应 `include` 时该字段为空，属预期行为，不视为缺陷。

## 6. 展示

内置工具的结果可能出现在消息文本标注、调用项内或独立项三种位置，但统一以调用胶囊展示，点击胶囊展示对应原始结构。

### 6.1 调用记录

- 每个内置工具调用项以调用胶囊展示，复用现有工具调用胶囊样式。
- 胶囊显示工具类型和关键参数（如 web_search 的查询词、shell 的命令、code_interpreter 的代码摘要）。

### 6.2 结果为消息文本标注（web_search 等）

- web_search 的结果以标注形式附着在模型回复文本中（含标题与链接）；file_search 等的标注同样以此形式出现。
- 标注作为一个独立胶囊展示，点击胶囊展示整个标注数组的原始结构；其中的链接可点击、在应用内打开。
- 存储与展示均为原始标注结构，不解析、不去重、不渲染成引用列表，与其它内置项展示口径一致。

### 6.3 结果在调用项内（code_interpreter）

- 结果位于调用项自身的输出字段内（如日志、图片）。
- 通过调用胶囊展示；点击胶囊展示整个调用项的原始结构，链接可点击。

### 6.4 结果为独立项（shell）

- shell 的结果作为独立的输出项返回（含 exit code、stdout、stderr）。
- 通过调用胶囊展示；点击胶囊展示整个输出项的原始结构。

## 7. 回传

1. 在同一服务商家族内组装下一轮请求时，把已持久化的内置工具项按原序原样放回输入数组。
2. 内置工具项仅按服务商家族门控，同家族即可回传，不要求相同模型 ID；内置工具项不含模型绑定的加密内容。
3. reasoning 加密内容维持既有规则：按服务商家族与模型 ID 门控，跨模型时剥离。
4. 切换到不支持该结构的服务商家族时，内置工具项整体不回传。
5. 内联载体（标注 annotations）不作独立输入项回传，而随所属助手文本内嵌回传：
   - 标注同样只按服务商家族门控。
   - 若该助手轮次没有任何文本可承载标注，则丢弃标注。
   - 采集时全量保留标注（含位置锚点、全部类型、不去重）以支持精确回传。

## 8. 验收标准

1. 助手消息中的内置工具项被完整采集并按原序持久化，重启后仍在。
2. web_search、code_interpreter、shell 三类调用均以调用胶囊展示，显示工具类型与关键参数。
3. web_search 的标注以独立胶囊展示，点击后展示完整标注数组的原始结构，其中链接可点、应用内打开。
4. code_interpreter 胶囊点击后展示完整调用项结构；shell 胶囊点击后展示完整输出项结构。
5. 同家族跨模型回传内置工具项成功，模型能复述上一轮工具结果。
6. 同家族跨模型时 reasoning 加密内容被剥离，请求不因加密内容被拒绝。
7. 切换到非同家族服务商时内置工具项不回传，且不产生结构错误。
8. 数据库版本不变、无迁移。
9. 用户未开启对应 `include` 时缺少结果明细字段属预期，展示与回传均不报错。
10. 标注随对应助手文本一起回传，同家族跨模型下模型仍能看到上一轮引用来源；无文本可承载时安全丢弃。
11. 未在专线处理的输出项类型（含未来新增内置工具）无需改代码即被采集、展示、回传。
